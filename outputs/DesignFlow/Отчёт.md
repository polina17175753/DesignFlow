## Введение

Дизайнеру необходимо одновременно контролировать несколько проектов, планировать задачи и учитывать поступающие оплаты. При ведении этих сведений в разрозненных заметках становится сложнее отслеживать состояние работы и финансовые итоги. Цель курсового проекта — создать учебную консольную программу DesignFlow, объединяющую базовый учёт проектов, задач и платежей.

Для достижения цели поставлены задачи: разработать меню приложения; реализовать три функциональных раздела; связать задачи и платежи с проектами; обеспечить сохранение данных между запусками; подготовить проект к совместной разработке с использованием Git и GitHub.

## 1. Описание проекта

DesignFlow — консольное приложение на языке C#. Пользователь выбирает нужный раздел из главного меню и выполняет операцию в соответствующем подменю.

### 1.1 Управление проектами

Программа позволяет добавлять проект с названием и именем клиента, просматривать список проектов и менять статус проекта. Доступны статусы «Запланирован», «В работе» и «Завершён». Каждому проекту назначается числовой идентификатор.

### 1.2 Управление задачами

Задача создаётся для существующего проекта. Пользователь может просмотреть задачи и отметить открытую задачу выполненной. В списке отображаются название проекта и состояние задачи.

### 1.3 Учёт платежей

Платёж записывается для выбранного проекта. Для каждой записи сохраняются сумма, комментарий и дата. Программа показывает историю платежей, сумму по каждому проекту и общий итог.

## 2. Структура и хранение данных

Проект разделён на модели данных, пользовательский интерфейс, сервисную логику и хранилище. `Program.cs` отвечает за меню и ввод; `Models.cs` содержит типы проекта, задачи, платежа и статуса; отдельные сервисы выполняют операции каждого раздела. `DataStore.cs` загружает и сохраняет данные в JSON-файл `designflow-data.json`.

Такое разделение помогает независимо развивать функции проекта, задач и платежей. Связь задачи и платежа с проектом задаётся через идентификатор проекта.

## 3. Использование Git и GitHub

Для выполнения командной части необходимо создать удалённый репозиторий GitHub и локальный репозиторий, отправить начальную версию, добавить второго разработчика и вести изменения в отдельных ветках. Рекомендуемые ветки: `feature/projects`, `feature/tasks`, `feature/payments`; после разработки их следует объединить в `final`, а затем в `master`.

Команды настройки, публикации и слияния приведены в `README.md`. Перед сдачей необходимо выполнить их в установленном Git, указать личные данные автора коммитов, подставить URL своего репозитория и сохранить подтверждающие скриншоты GitHub и истории веток.

## 4. Запуск программы

Требуется .NET 8 SDK. В терминале из папки проекта выполнить:

```powershell
dotnet run
```

Данные приложения сохраняются в `designflow-data.json` рядом с исполняемым приложением.

## Заключение

В рамках проекта подготовлена консольная версия DesignFlow с тремя разделами: управление проектами, задачами и платежами. Реализованы добавление и просмотр записей, изменение статуса проекта, завершение задачи и подсчёт поступивших сумм. Данные сохраняются в JSON-файл.

Программная часть подготовлена к локальной сборке. Для завершения практической части GitHub необходимо установить Git, создать репозиторий в аккаунте студента, пригласить второго участника, выполнить коммиты в ветках и объединить их согласно заданию. Сведения о проекте за предыдущий семестр и фактические результаты командной работы следует добавить в итоговый отчёт.
